# Discord → Googleスプレッドシート同期Bot

## 最短導入（3ステップ）

### 1. GitHubへ置く

この `discord-sheets-bot` フォルダの中身を、そのままGitHubリポジトリへアップロードします。

### 2. RailwayでDeploy

Railwayで **New Project → Deploy from GitHub repo** を選び、このリポジトリを指定します。

### 3. RailwayのVariablesへ5項目を登録

```text
DISCORD_BOT_TOKEN          Discord Botのトークン
DISCORD_GUILD_ID           DiscordサーバーID
ROSTER_ROLE_ID             名簿に表示する人が持つロールID
GOOGLE_SPREADSHEET_ID      1YjZJaEqN5dyqnRZUJ2PNrdkSulE7vOrARVZ_R6iCNcA
GOOGLE_SERVICE_ACCOUNT_JSON  Googleから取得したJSONファイルの中身全部
```

対象ロールを複数にする場合だけ、カンマ区切りで追加できます。

```text
ROSTER_ROLE_IDS=ロールID1,ロールID2
EXCLUDE_ROLE_IDS=休職ロールID,退職ロールID
```

登録後に **Deploy** または **Redeploy** を押します。ログへ次が出れば成功です。

```text
Discord接続完了
全件同期完了
```

初回導入後は、Discord側のIntent設定が遅れていてもBotが30秒ごとに自動再接続します。GitHub連携のAutodeployを有効にすると、コード更新時のRedeploy操作も不要です。

## 必須の事前設定

- Discord Developer PortalのBot設定で **SERVER MEMBERS INTENT** をオンにする。
- Googleサービスアカウントのメールアドレスを対象スプレッドシートへ「編集者」で共有する。
- スプレッドシートの「設定」で表示カテゴリを `ランク` にし、各DiscordロールIDを入力する。
- ランク欄には有効な `体験` と `解雇者` を1件ずつ用意する。

## 動作

- `ROSTER_ROLE_ID` を持つメンバーだけ「従業員」へ表示します。
- `ROSTER_ROLE_ID`（Police Officer）だけを持ち、階級ロールがないメンバーは適用ランクを `？？？？` と表示します。
- Discord上でBot以外のロールが1つもないメンバー、またはサーバーから脱退したメンバーは「従業員」から自動削除します。
- 複数の階級ロールがある場合、「ランク設定」の優先度が最も小さい階級を採用します。
- 「従業員」は「ランク設定」の優先度が高い階級から並び、同じ階級内では表示名の昇順で自動整列します。
- ロール変更、加入、脱退をリアルタイム反映します。
- Bot起動時には全メンバーを再確認します。
- 「従業員」の各行で「変更後ランク」を選び、緑色の「実行ボタン」をクリックすると、通常30秒以内にDiscordへ反映します。昇格・降格・解雇を1つの操作欄で扱えます。
- 「適用ランク」を直接変更した場合もDiscordへ反映し、Discord側で階級ロールを変更した場合はスプレッドシートへ反映する双方向同期です。
- 階級ロールが残った状態でPolice Officerロールだけが外れた場合は、BotがPolice Officerロールを自動で付け直します。
- 解雇は名簿対象ロールと階級ロールを解除して「解雇者」ロールを付与し、「解雇者管理」へ氏名・ID・最終ランク・解雇日を自動記録します。
- Discord側で「解雇者」ロールを直接付けた場合も、Police Officerロールを自動で解除します。
- 「解雇者管理」で「対応署員」を入力して「手続き完了」にチェックすると完了日が自動記録され、その7日後に「従業員」名簿から自動削除されます。退職履歴は「解雇者管理」に残ります。
- 同じDiscordユーザーIDの行が複数ある場合、手入力項目を残しながら起動時に1行へ統合します。

操作の監視間隔を変える場合だけ、Railway Variablesへ次を追加します。Google Sheetsの読込上限を守るため、未設定時と最小値は30000ミリ秒です。

```text
ACTION_POLL_INTERVAL_MS=30000
```

BotのDiscordロールは、操作対象の名簿ロール・階級ロールより上へ配置してください。下にあるロールはDiscordの仕様上変更できません。
「解雇者」ロールもBotのDiscordロールより下へ配置してください。

## STEP2 面接Bot

STEP1の書類選考で `FINAL・合格・合格発表済み` になった応募者には「書類合格者」ロールが自動で付き、同じ応募IDのままSTEP2へ進みます。

1. 「設定」で表示カテゴリを `面接` にし、実行チャンネル、面接官ロール、面接投票チャンネル、面接合格発表チャンネルを設定します。
2. 表示カテゴリを `面接質問` に切り替え、質問セットを追加・並べ替えます。
3. 指定チャンネルで `/mensetu` を実行し、面接する応募者を選択します。
4. Botが全質問を常時表示します。「この質問に回答」から1問ずつ入力すると、その場で自動保存されます。
5. 必須質問をすべて回答すると「回答完了・投票へ」が有効になり、STEP1とは別のチャンネルで面接投票を作成します。
6. 設定票数または期限で自動確定し、合格時だけ別の発表チャンネルへ設定文と本人メンションを送ります。

ロールは選考段階と自動同期します。面接合格では「面接合格者」を付与して「書類合格者」を解除し、面接不合格でも「書類合格者」を解除します。面接合格者は「採用手続き管理」へ自動追加されます。備品などの手続きを終えたら対応署員を入力して「手続き完了」をチェックしてください。Botが「体験」と「Police Officer」を付与し、「面接合格者」を解除して完了日時を記録します。

「設定」の書類選考欄にある書類合格ロールIDと、面接欄にある面接合格ロールIDを変更できます。ロールIDが空欄の場合は、Discord上の `書類合格者` / `面接合格者` という名前から一意に解決します。途中で画面を閉じても、同じ面接官が `/mensetu` を再実行すると進行中の回答画面を再開できます。

応募者選択・質問・回答は実行した面接官だけに見える表示です。面接投票には質問と回答を掲載しますが、STEP1の応募書類は再掲しません。合格発表にも応募書類・面接回答を掲載しません。

候補者が25人を超える場合は `/mensetu search:検索語` で応募ID・名前・Discordユーザー名を絞り込めます。面接官ロールIDを空欄にした場合、面接実行チャンネルを閲覧できる人が実行できます。

## 署員個票

- 「署員個票」の青い検索欄へ、17〜20桁のDiscordユーザーID、`DC-` 付き社員ID、またはDiscordメンションを入力すると、現在の氏名・階級・ロール・係数・報告内容・最終操作を1人分ずつ表示します。
- 署員別の報告・申し送りは「従業員」の報告欄へ入力します。並べ替え後も社員IDと同じ行に保持され、署員個票と `/syoin` へ自動反映されます。
- `該当なし`、`形式エラー`、`重複あり`を個別に表示し、重複時に別人の情報を誤表示しません。個票は数式参照のためBotの監視間隔を待たず、Sheets APIの読込回数も増やしません。
- Discordでは `/syoin user:@対象` または `/syoin id:DiscordユーザーID` で同じ個票を自分だけに表示できます。引数を省略した場合は自分自身を検索します。
- `/syoin` はPolice Officerロールを持つ署員またはロール管理権限を持つ管理者だけが利用できます。応募書類・面接回答・解雇情報は表示しません。

## 項目やランクの追加

- 「従業員」の列を追加・並べ替えても、Botは見出し名を探すため壊れません。
- Discordの識別には「社員ID」（`DC-DiscordユーザーID`）を使うため、DiscordユーザーID・入社日・手動ランク・同期ランク列は不要です。
- Botに必要な見出しがない場合は、2行目の右端へ自動追加します。
- 「設定」のランク欄へ新しい階級を追加すると、次の同期から自動で査定対象になります。
- 上部の表示カテゴリで、ランク・ボーナス回・書類選考・面接・面接質問・連携を切り替えられます。
- 設定監査で異常を検知した場合は設定状態へ表示し、その周期は旧設定へ安全にフォールバックします。
- 独自の列はBotが上書きしないため、自由に追加して利用できます。

## セキュリティ

`.env`、Botトークン、Google JSON鍵はGitHubへアップロードしないでください。秘密情報はRailwayのVariablesだけへ保存します。
